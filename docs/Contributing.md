We appreciate any help reporting errors in the plugin, as well as suggestions and improvements to implement. But we appreciate even more Pull Requests (PR) with direct help to resolve errors or improve the plugin.

# When reporting an error (bugs)

Please verify that the error you found does not occur in a clean, up-to-date WordPress installation (updated both our plugin and WP).

And search. Use the search option within Issues to see if anyone has already reported what you're trying to solve (see closed Issues). Please.

# Suggestions

They are welcome. Of course, this doesn't obligate us to accept them all or implement them immediately. Everything depends on several factors.

For example, if the suggestion makes sense for a potential majority of plugin users, and not just your particular case.

Time. Work on this plugin is done ad-honorem, so no matter how great your suggestion is, if it involves a lot of time to implement, your need won't necessarily be satisfied quickly.

If your suggestion comes with a Pull Request (resolved by yourself), even better ;D

# How to contribute directly to Plugin development (Pull Requests)

To contribute directly (PR), you should consider:

* One PR per feature, improvement, or bug fix. If you plan to make several improvements or fix different bugs, please create a branch for each fix and/or improvement you want to make in your repository. Then make a PR for each of that set of changes. It's easier to review changes for each improvement or bug resolved in separate PRs than a bunch of changes throughout the plugin in a single PR without knowing what they resolve or improve.
* All contributions must follow [PSR-12](https://www.php-fig.org/psr/psr-12) standards.
* We use [Composer](http://getcomposer.org/) for PHP. And you should use it too.
* For all third-party libraries (PHP, CSS, or JS) the license must be compatible with the GPLv2 license (just like WordPress).
* If you're going to use third-party code snippets, for example, from GitHub (Gists) or StackOverflow, please give appropriate credit to the code snippet creator. With a comment above the code snippet and the URL where the original author published that snippet. In the case of Stackoverflow, [attribution is required](https://meta.stackexchange.com/questions/272956/a-new-code-license-the-mit-this-time-with-attribution-required) via a URL to the post where the snippet was found.
* Code in English. All variable names, functions, classes, methods, comments, etc. should be clear (over abbreviated) and written in English.
* Comment your code. It helps us all understand what you're trying to do. Use docBlocks (/** */) on functions or methods.
* Have tested your changes in a clean and updated WordPress installation, with [debug mode activated](https://codex.wordpress.org/Debugging_in_WordPress), with WooCommerce installed and updated to the most recent version, and with our plugin installed and updated to the most recent version. No warnings, errors, or exceptions should be triggered by your changes to the plugin.

If you have suggestions regarding this code for plugin contributions, please open a new discussion about it, and let's talk ;)

Thank you in advance for your time and help!
